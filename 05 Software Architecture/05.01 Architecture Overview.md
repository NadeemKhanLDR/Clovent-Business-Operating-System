# 05.01 Architecture Overview

## Clovent Business Operating System (CBOS) Architecture

CBOS follows **Clean Architecture**, **Domain-Driven Design (DDD)**, **CQRS**, and **Vertical Slice Architecture**.

### System Layers & Tooling Architecture

```
[ Clovent.CLI ] (Thin CLI Presentation Layer)
       │
       ▼
[ Clovent.Generator ] (Generator Business Logic)
       │
   ┌───┴───────────────────────┬────────────────────────┐
   ▼                           ▼                        ▼
[ Clovent.Templates ]  [ Clovent.Documents ]    [ Clovent.Core ]
(Code Generation)     (Obsidian Vault Docs)    (Domain & Base Services)
   │                           │                        │
   └───────────────────────────┴────────────────────────┘
                               │
                               ▼
                      [ Clovent.Shared ]
```

### Module Structure Standards

Every module generated in CBOS follows Clean Architecture:

- **Domain Layer**: Aggregates, Entities, Value Objects (`EntityId`), Domain Events (`IDomainEvent`), Specifications, Domain Interfaces.
- **Application Layer**: CQRS Commands (`IRequest<T>`), Queries, DTOs, FluentValidation Validators, Handlers (`IRequestHandler<TCommand, TResponse>`).
- **Infrastructure Layer**: EF Core `DbContext`, `IEntityTypeConfiguration<T>`, Repositories, External Services.
- **UI Layer**: WinForms DevExpress User Controls (`XtraUserControl`), ViewModels, UI Data Bindings.
- **Documentation**: Obsidian markdown notes linked with `[[...]]`.
